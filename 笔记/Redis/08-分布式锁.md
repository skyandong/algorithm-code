# 8. 分布式锁

## 基础实现
```
SET lock_key <request_id> NX PX 30000
```
- `NX`:不存在才设置(互斥)
- `PX 30000`:设过期,防止持有方宕机导致死锁
- value 用**唯一 request_id**(UUID),用于释放时验证归属

## 释放锁(Lua 保证原子性)
```lua
if redis.call('get', KEYS[1]) == ARGV[1] then
    return redis.call('del', KEYS[1])
else
    return 0
end
```
- 必须用 Lua:避免"先 get 判断再 del"之间被其他客户端删掉/重入

## 过期续期问题
- 业务执行超过锁 TTL → 锁被自动释放,其他客户端拿到锁 → 并发问题
- **Redisson watchdog**:后台线程定期(默认 TTL/3)续期,业务完成才停止

## Redlock(Redis 作者提出)
- 在 N(通常 5)个独立 Redis 实例上依次加锁
- 超过半数(N/2+1)成功且总耗时小于锁有效期 → 加锁成功
- **争议**:Martin Kleppmann 指出 GC pause / 时钟漂移会破坏安全性;antirez 反驳
- 实际生产:单 Redis 实例锁 + 容错降级,或直接用 ZooKeeper / etcd
