# 3. 持久化

## RDB(快照)
- 二进制文件,定时 `bgsave` 触发
- **`bgsave` 利用 fork + COW(Copy-On-Write)**:子进程写 RDB,父进程继续处理请求;父进程修改某页时,内核才复制该页
- 恢复快,文件小;但宕机可能丢最后一次快照后的数据

## AOF(追加日志)
- 记录每条写命令
- **fsync 策略**:
  - `always`:每条命令都刷盘,最安全最慢
  - `everysec`:每秒刷一次(推荐,性能与安全平衡,宕机最多丢 1 秒)
  - `no`:交由 OS 决定
- **AOF 重写(`bgrewriteaof`)**:fork 子进程,把当前内存状态转成命令重写,压缩文件体积(去重复命令、过期 key)
- 数据更完整,但文件大、恢复慢

## 混合持久化(Redis 4.0+)
- `aof-use-rdb-preamble yes`
- AOF 文件前半段是 RDB 格式(全量快照),后半段是增量命令
- 重启时先加载 RDB(快),再重放 AOF 增量(少丢),兼具两者优点
- Redis 5.0 默认开启
