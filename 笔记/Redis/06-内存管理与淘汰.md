# 6. 内存管理与淘汰

## 过期 Key 删除机制
- **惰性删除**:访问时才检查过期,删除(被动,兜底)
- **定期删除**:每隔一段时间随机抽样检查并删除过期 Key(主动)
- 两者结合,平衡 CPU 与内存

## 大 Key 删除阻塞
- 删除大 Key(如几十万元素的 Hash)会阻塞主线程
- Redis 4.0+:`UNLINK` / `lazyfree-*` 配置,**异步释放内存**
- 删除大集合务必用 `UNLINK` 而非 `DEL`

## 淘汰策略(8 种,`maxmemory-policy`)
| 策略 | 范围 | 说明 |
|------|------|------|
| `noeviction` | - | 不淘汰,写报错(默认) |
| `allkeys-lru` | 所有 | 近似 LRU |
| `allkeys-lfu` | 所有 | 近似 LFU(Redis 4.0+) |
| `allkeys-random` | 所有 | 随机 |
| `volatile-lru` | 设了过期的 | 近似 LRU |
| `volatile-lfu` | 设了过期的 | 近似 LFU |
| `volatile-random` | 设了过期的 | 随机 |
| `volatile-ttl` | 设了过期的 | 优先删快过期的 |

- **近似 LRU**:Redis 不维护全局链表(太贵),而是**随机采样**(默认 5 个,`maxmemory-samples` 可调)选最久未用的淘汰
- **LFU**:用 Morris 计数器 + 随时间衰减,更贴合热点访问模式
