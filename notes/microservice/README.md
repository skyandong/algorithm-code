# microservice 微服务治理

> **主线认知：** 微服务的全部代价是「**网络成了函数调用**」——治理件解决由此产生的五类问题：**找不到**（注册发现）、**改不动**（配置）、**连不稳**（熔断限流）、**看不见**（可观测）、**说不清**（网关路由）。

## 跑实验

```bash
go run ./experiments/ all          # 全部
go run ./experiments/ circuitbreaker   # 单跑（可选: registry/config/gateway/trace）
go run -race ./experiments/ all    # data race 检查（零告警）
```

06 为概念篇无实验（前五篇能力的居住形态重组），配套现成 demo 见 `demos/tracing`。

## 实验数据锚点表

| 实验 | 锚点 | 实测 |
|---|---|---|
| 01 注册中心 | 宕机实例 TTL 内摘除；优雅退出耗时 << TTL；僵尸实例（心跳正常+探针失败）被摘 | ✓ |
| 02 配置中心 | 更新瞬间并发读数万次，中间态 = 0；坏配置被校验拒绝；100 实例应用时间摊开 0~50ms | ✓ |
| 03 熔断器 | closed→open（错误率 50%+样本 20）；open 期 19 个请求快速失败；冷却期后探活 2 连成恢复；令牌桶突发放行 10/12 | ✓ |
| 04 网关 | 同 uid 20 次请求 100% 恒定同版本（灰度粘性）；分桶 20%±5；路由表热更新 404→200 | ✓ |
| 05 trace | 5 个 span 全部同一 trace_id；parent 指针建树正确；db 40ms 占 order 78%（慢段定位） | ✓ |

## 重点回顾自测清单

- [ ] 注册中心 CP/AP 的张力？为什么实践中差距小于理论（调用方本地缓存）？
- [ ] 心跳和健康检查探针的区别（进程活着 ≠ 能服务）？
- [ ] 优雅下线四步？为什么 TTL 摘除是给宕机兜底而不是给发布用的？
- [ ] 配置热更新的三步链路（watch→校验→换快照）？为什么绝不逐字段热改？
- [ ] 灰度期间配置秒级新旧并存怎么处理（粘性 key / 版本协商 / 随机延迟摊开）？
- [ ] 三板斧各自的保护对象？为什么熔断在调用方？
- [ ] 熔断器三态机 + 四个关键参数（错误率/最小样本/冷却期/探活数）的 WHY？
- [ ] 漏桶 vs 令牌桶（出口恒速 vs 入口突发）？
- [ ] 网关/BFF/LB 三层智能递增？中间件链为什么限流在鉴权前？
- [ ] 灰度为什么用 uid 取模不用随机（粘性）？
- [ ] 三支柱的漏斗关系？四个黄金指标？为什么 P99 不用均值？
- [ ] trace_id 怎么透传（进程内 context / 跨进程 header）？
- [ ] 头部采样 vs 尾部采样（错误和慢请求 100% 保留的价值）？
- [ ] SDK vs sidecar 的 trade-off（三税 vs 两跳）？什么规模上网格才划算？
