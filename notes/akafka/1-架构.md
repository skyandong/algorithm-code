# 一、基础架构与核心概念

| 概念 | 说明 |
|------|------|
| Topic | 逻辑上的消息队列，生产者发消息到 Topic，消费者从 Topic 订阅 |
| Partition | Topic 的物理分片，每个 Partition 是有序的日志（Log），不同 Partition 之间无序 |
| Broker | Kafka 服务器节点，负责存储和转发消息 |
| Producer | 生产者，负责向 Topic 发送消息 |
| Consumer | 消费者，负责从 Topic 拉取消息 |
| Consumer Group | 消费者组，组内消费者共同消费一个 Topic，一条消息只会被组内一个消费者消费 |
| Offset | 消息在 Partition 中的唯一标识（位移），消费者用 Offset 记录消费进度 |
| Replication | 副本机制，每个 Partition 有多个副本（Leader + Follower），保证高可用 |

**背诵口诀：** Topic 管逻辑，Partition 管物理，Leader 管读写，Follower 管同步，Offset 管进度，Group 管竞争。

# 八、Kafka 架构演进：ZooKeeper → KRaft

| 模式 | 特点 |
|------|------|
| ZooKeeper 模式（< 3.3） | 依赖 ZK 管理元数据、Controller 选举，运维复杂，ZK 瓶颈 |
| KRaft 模式（Kafka 2.8+ 预览，3.3+ 正式） | 去掉 ZK，用 Raft 协议在 Broker 内部选举 Controller，元数据也存于 Kafka 内部，简化架构，提升性能 |

**面试金句：** Kafka 正在去 ZooKeeper，KRaft 模式用内置的 Raft 共识算法管理元数据，解决了 ZK 脑裂和性能瓶颈问题，是未来的主流方向。
