# nginx 面试一口答清单

> 从各篇笔记提炼的"张口就来"清单：被问到要能不带停顿直接说出来。
> 对应章节：`01-核心架构与配置` ~ `06-场景题专题`，实验代码在 `experiments/`。
>
> **记忆主线：nginx = master-worker + 事件驱动。master 管理不干活，worker 用 epoll 扛连接；反代是"解析再转发"，两头 keepalive；TLS 只终止在 nginx，后端纯 HTTP 靠透传头感知。**

---

## 一、核心架构（最高频）

### 1. nginx 为什么快？
- **master-worker 模型**：master 只管理（绑端口、fork、热重载），worker 干活
- **事件驱动 + epoll**：一个 worker 单线程事件循环扛几万连接，连接是 fd 不占线程栈
- **worker 数 = CPU 核数**，无锁无上下文切换，吃满多核
- 对比 Apache prefork（一连接一线程）：nginx 的连接只是 epoll 上一个 fd，内存开销差几个数量级

### 2. master 和 worker 各干什么？
- master（root）：读配置、绑 80/443 特权端口、fork worker、热重载、拉活挂掉的 worker
- worker（降权用户）：epoll 事件循环处理请求
- **特权分离**：worker 被攻破也拿不到 root

### 3. nginx -s reload 做了什么？（必考）
1. master 用**新配置** fork 新 worker
2. 旧 worker 处理完**存量连接**再退出
3. 监听 socket 始终不关 → **不停机、不丢请求**
- 改完配置先 `nginx -t` 再 reload

### 4. location 匹配优先级？
`=` 精确 → `^~` 前缀（跳过正则）→ `~ / ~*` 正则（按顺序）→ 最长前缀
**`^~` 的存在意义**：前缀命中后不被正则劫走。

### 5. rewrite 的 last 和 break？
`last`：重写后**重新匹配 location**；`break`：停止重写直接处理；`redirect`/`permanent`：302/301。

## 二、反向代理与负载均衡

### 6. proxy_pass 带不带斜杠？
- 带 URI（`http://backend/`）→ **吃掉** location 前缀
- 不带（`http://backend`）→ 原样拼接
- 指向 upstream 名字才能用负载均衡和 keepalive

### 7. 负载均衡策略有哪些？
轮询（默认）/ weight / ip_hash / least_conn / 一致性哈希（hash 模块）。
`max_fails + fail_timeout` = 被动健康检查（N 秒内挂 M 次摘除 N 秒）。

### 8. 反代后后端怎么知道真实客户端 IP / 原始协议？
`proxy_set_header` 四件套：`Host`、`X-Real-IP`、`X-Forwarded-For`（追加链，**最左可伪造**，从右往左取第一个可信 IP）、`X-Forwarded-Proto`。

### 9. 反代为什么要开 keepalive？怎么开？
三件套缺一不可：
```nginx
upstream backend { keepalive 32; }
proxy_http_version 1.1;
proxy_set_header Connection "";   # 清掉默认的 close
```
不开 = 每请求一次握手 + TIME_WAIT 堆积 + 端口耗尽。

### 10. 502 和 504 的区别？
502 = 上游返回无效响应（挂了/端口没监听）；504 = 上游超时（超 proxy_read_timeout）。
排障：看 `$upstream_addr` 确认打到谁，比 `$request_time` 和 `$upstream_response_time` 的差值定位慢在哪层。

## 三、限流与安全

### 11. nginx 限流是什么算法？
**漏桶**。`rate` 平均速率（按毫秒平滑）、`burst` 桶容量、`nodelay` 决定桶内请求"立即放行"还是"排队"。超限返回 `limit_req_status`（默认 503，常改 429）。

### 12. burst 加不加 nodelay 的区别？（易错）
- 不加：多余请求**排队等**，按 rate 节奏处理，不丢但延迟高
- 加：前 rate+burst 个**立刻全放**，之后立即拒 —— API 场景用户宁可失败不想等

### 13. limit_req_zone 的 key 为什么要用 $binary_remote_addr？
二进制 IPv4 固定 4 字节（文本 7-15），**10MB 能存约 16 万 IP 状态**，省共享内存。

### 14. nginx 层限流 vs 应用层限流？
nginx：单机、挡 IP 级滥用、把脏流量挡在进程外；应用/Redis 层：集群全局、业务维度精细控制。**多层限流是标准实践**：边缘粗过滤 + 应用细控制。

### 15. 常见安全加固？
`server_tokens off`（藏版本）、`client_max_body_size`（挡大 body）、超时收紧（防 Slowloris 慢连接攻击）、安全响应头、allow/deny ACL。

## 四、HTTPS / TLS 终止

### 16. 什么是 TLS 终止？为什么放 nginx？（本模块铁律）
HTTPS 在 nginx 解密成纯 HTTP 再转发。证书/私钥/协议/套件全在 nginx 层：
- 加解密 CPU 成本集中在边缘，后端把 CPU 留给业务
- 证书续期/协议升级只改 nginx，**后端零代码改动零部署**
- 后端感知 https 只靠 `X-Forwarded-Proto` 头

### 17. 自签证书三个易错点？
必须带 **SAN**（浏览器不认 CN）；`-nodes` 免交互密码；curl 加 `-k`（不在信任链）。

### 18. ssl_protocols 配什么？
`TLSv1.2 TLSv1.3`（1.0/1.1 有漏洞）；1.3 的套件不受 ssl_ciphers 控制（内置强制安全）。

## 五、性能调优

### 19. sendfile 是什么？
静态文件零拷贝：数据全程内核态（page cache → 网卡），省 2 次用户态拷贝。配 `tcp_nopush`（攒 MSS）+ `tcp_nodelay`（keepalive 上禁 Nagle）。

### 20. 哪些场景必须 proxy_buffering off？
**SSE / 流式接口**：buffering 会攒着不吐，实时变批量；还要放大 `proxy_read_timeout`（它是**两次读之间的间隔**，不是总耗时——所以心跳能防超时）。

### 21. worker_connections 怎么算？
总并发 ≈ worker_processes × worker_connections（反代时上游连接也占）；还要保证 `worker_rlimit_nofile` 和系统 ulimit 跟得上。

## 六、场景题速答

### 22. SPA 刷新 404？
`try_files $uri $uri/ /index.html;` 回落到入口。

### 23. WebSocket 反代要配什么？
`proxy_http_version 1.1` + `Upgrade $http_upgrade` + `Connection "upgrade"`（唯一不清空 Connection 的例外）+ 放大 read_timeout。

### 24. 灰度发布怎么做？
权重灰度（weight 9:1）/ cookie 定向灰度（map）/ server down 摘流量，配合 reload 零丢包。

### 25. 秒杀入口怎么配？
边缘 limit_req 挡 IP 刷子 → 静态化减负 → 排队模式保护后端 → 后端 Redis 预扣快速失败。**限流的目的是让多余流量便宜地失败，不是让它们成功。**

### 26. POST 被 nginx 重试导致重复下单？
默认**不会**：`proxy_next_upstream` 对已发送到上游的非幂等请求（POST/LOCK/PATCH）默认不重试，这是 nginx 内建的保护。出事的场景：显式配了 `non_idempotent`，或请求还在连接阶段没发出（此时换机重试是安全的）。要放开 POST 重试，后端必须先做幂等键。
