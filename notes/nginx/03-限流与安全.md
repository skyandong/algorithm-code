# 限流与安全

> **核心认知：nginx 限流是"漏桶算法"，两个维度（rate + burst）控制：rate 定平均速率，burst 允许突发排队，nodelay 决定排队还是直接放行。
> 单机限流、以内存换性能（10MB 共享内存能存 16 万个 IP 状态），配置简单但重启丢失、多机不共享。**

---

## limit_req：漏桶限流（最常用）

```nginx
# 定义限流规则：以客户端 IP 为 key，10MB 共享内存，速率 5 请求/秒
limit_req_zone $binary_remote_addr zone=req_limit:10m rate=5r/s;

server {
    location /api/ {
        # 应用规则：突发容量 10，不排队
        limit_req zone=req_limit burst=10 nodelay;
        limit_req_status 429;        # 超限返回 429（默认 503）
        proxy_pass http://backend;
    }
}
```

三个参数的精确含义：

| 参数 | 含义 | 直觉理解 |
|------|------|----------|
| `rate=5r/s` | 平均速率，实际按毫秒平滑计 | 每 200ms 放一个"令牌" |
| `burst=10` | 桶容量，允许的突发排队数 | 瞬间来 15 个，10 个进桶 |
| `nodelay` | 桶里的请求**立刻放行**，桶只记账 | 不加：请求在 nginx 里排队延迟回包；加：立刻发，超桶才 429 |

**`burst` 不加 `nodelay` 的语义（易错）**：请求不丢，但要按 rate 的节奏排队被处理——超出 burst 的请求才会被拒。加 `nodelay`：前 burst 个立刻全放，之后全拒，适合 API（用户宁可失败也不想等）。注意漏桶没有"rate 窗口额度"：瞬发请求的放行数由 burst 决定，rate 只决定后续漏出速度。

对应实验：`experiments/04_ratelimit.go` 瞬发 20 个请求，数 429 的个数（预期 ≈ 20 - burst = 10）。

### 为什么要自己写 key：`$binary_remote_addr`

- `$remote_addr` 是字符串，一个 IPv4 占 7-15 字节；`$binary_remote_addr` 二进制固定 4 字节（IPv6 16 字节）
- **10MB ÷ 64B ≈ 16 万 IP 状态**，这就是官方注释里 1M 存 1.6 万 IP 的由来
- key 可以换：`$http_apikey`（按业务方限）、`$server_name`（按域名限）、`$arg_uid`（按参数限）

### limit_conn：并发数限制（和速率互补）

```nginx
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;
location /download/ {
    limit_conn conn_limit 5;      # 单 IP 最多 5 个并发连接
    limit_rate 1m;                # 每连接限速 1MB/s（下载站刚需）
}
```

速率限"总量"，并发限"占用"。下载站两个都要。

## 对比其他层的限流（面试高频三连）

| 层 | 工具 | 算法 | 分布式 | 适用 |
|----|------|------|--------|------|
| 接入层 | nginx limit_req | 漏桶 | ❌ 单机 | 挡 IP 级攻击/滥用 |
| 应用层 | 自研令牌桶（Go golang.org/x/time/rate） | 令牌桶 | 可配 Redis | 业务级精细控制 |
| 中间件 | Redis + Lua（衔接 notes/redis 11） | 滑动窗口 | ✅ | 集群全局限流 |

nginx 层的意义：**把最脏的流量挡在应用进程之外**，后端Go 进程都不用为垃圾流量分配 goroutine。多层限流是标准实践：边缘粗过滤 + 应用细控制。

## 安全加固清单（生产必做）

```nginx
# ① 隐藏版本号：Server: nginx 变成 nginx（无版本），响应头和错误页都生效
server_tokens off;

# ② 请求体大小：挡超大 body 攻击（默认 1m，上传场景单独调）
client_max_body_size 10m;

# ③ 超时收紧：慢连接攻击（Slowloris）靠占住连接
client_header_timeout 10s;
client_body_timeout   10s;
keepalive_timeout     65s;
send_timeout          30s;

# ④ 安全响应头(X-XSS-Protection 已被现代浏览器废弃,改用 CSP)
add_header X-Frame-Options        SAMEORIGIN;
add_header X-Content-Type-Options nosniff;
add_header Content-Security-Policy "default-src 'self'";   # 按业务放宽

# ⑤ IP 黑白名单（接入层最原始的 ACL）
location /admin/ {
    allow 10.0.0.0/8;
    deny  all;
}
```

**WHY 超时要收紧**：每个连接挂在 epoll 上也占内存和 fd，慢连接攻击就是用几百个字节每分钟的速度养着上万连接，把 `worker_connections` 吃光 → 正常用户 503。

## 静态文件与防盗链

```nginx
location ~* \.(jpg|png|css|js)$ {
    root /var/www/static;
    expires 30d;                          # 浏览器缓存 30 天（强缓存）
    valid_referers none blocked server_names *.example.com;
    if ($invalid_referer) {               # Referer 不在白名单 → 403
        return 403;
    }
}
```

防盗链的诚实结论：Referer 可伪造，只能挡小白；真要防资源被盗用，用带过期时间的签名 URL（衔接 oss-lab 的 OSS 签名 URL 是同一思想）。
