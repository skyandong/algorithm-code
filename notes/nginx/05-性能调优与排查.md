# 性能调优与生产排查

> **核心认知：nginx 性能 = 零拷贝 + 事件驱动 + 把等待都异步化。90% 的"调优"就五件事：worker 数对齐核数、连接数放大、开 sendfile/tcp_nopush、开 gzip、压缩和上游都上 keepalive。
> 剩下的 10% 是排障：定位慢在 nginx 层还是 upstream 层，看 access log 的两个时间差。**

---

## 静态文件：零拷贝链路

```nginx
http {
    sendfile        on;      # 数据不经过用户态：内核 page cache → 网卡
    tcp_nopush      on;      # 配合 sendfile：攒满一个 MSS 再发，减少小包
    tcp_nodelay     on;      # keepalive 连接上禁用 Nagle，交互请求不攒包
    gzip            on;      # 压缩有 CPU 成本，只压文本类
    gzip_types      text/plain text/css application/json application/javascript;
    gzip_min_length 1k;      # 太小的包不值得压
    gzip_comp_level 5;       # 1-9，5 是性价比拐点
}
```

**sendfile 的 WHY（衔接 OS 知识）**：
不开时读文件 = 磁盘→内核缓冲→用户态→socket 缓冲→网卡，4 次拷贝 2 次系统调用；
sendfile = 数据全程在内核态流转，用户态只递文件描述符。静态文件服务吞吐差距可达数倍。

`tcp_nopush` 和 `tcp_nodelay` 看似矛盾（攒包 vs 不攒包），实际各管一段：nopush 管 sendfile 的大块响应头+数据，nodelay 管 keepalive 上的小块交互。

对应实验：`experiments/06_performance.go` 带 `Accept-Encoding: gzip` 请求大 JSON，验证响应被压缩。

## 缓冲与超时：反代场景的隐性坑

```nginx
proxy_buffering    on;      # nginx 先收满 buffer 再给客户端（默认 on）
proxy_buffers      8 16k;
proxy_busy_buffers_size 32k;
proxy_read_timeout 60s;     # 两次读上游之间的最大间隔（不是总耗时！）
proxy_connect_timeout 5s;   # 与上游建连超时
```

- **SSE / 流式接口必须 `proxy_buffering off`**（衔接 web/sse 实验）：buffering 开着，事件会被 nginx 攒着不吐，前端"实时"变"批量"
- `proxy_read_timeout` 是**间隔**不是总额：后端每 10s 推一次心跳就永不超时，这正是心跳的意义

## 系统层配套（nginx 之外的瓶颈）

```bash
# 文件描述符：nginx.conf 里 worker_rlimit_nofile 要 ≤ 这里
ulimit -n                     # macOS/Linux 默认可能只有 256/1024
sysctl kern.maxfiles          # 系统级上限（macOS）
sysctl net.inet.tcp.portrange #  TIME_WAIT 堆积时关注端口耗尽
```

顺序：worker_rlimit_nofile ≥ worker_connections × worker_processes，且 ≤ 系统上限。

## 生产排查手册（按症状索引）

### 慢
```bash
# 第一步永远是看 access log 的两个时间
$remote_addr [$time] "GET /api/x" 200 2.35 2.30 127.0.0.1:8081
#                        request_time ↑     ↑ upstream_time
```
- 两个时间都大 → 慢在后端，nginx 无罪
- request_time 大、upstream_time 小 → 慢在 nginx（限流排队 / buffering / 客户端网络）
- `$upstream_addr` 出现多值（`a:8081, b:8082`）→ 重试过，第一个失败了，查后端稳定性

### 502 / 504
```bash
# ① 后端活着吗
curl http://127.0.0.1:8081/hello
# ② nginx error.log 说什么
tail -f conf/logs/error.log    # connect() failed / upstream timed out 一目了然
# ③ 高并发下 502：大概率是 worker_connections 或文件描述符耗尽
```

### 连接数暴涨
```bash
netstat -an | grep 8080 | awk '{print $6}' | sort | uniq -c
# TIME_WAIT 巨大 → 上游没开 keepalive（回看 02 篇），或客户端没复用连接
```

### 配置改了没生效
```bash
nginx -t && nginx -s reload     # 忘 reload 最常见
ps -ef | grep nginx             # reload 后 master 的 start time 不变，worker 变新
```

## 压测方法论

```bash
# mac 自带没有 ab，用 wrk（brew install wrk）
wrk -t4 -c100 -d30s http://localhost:8080/hello
```

- 压 nginx 时注意：**压测工具本身也可能成为瓶颈**（本机回环 + 单工具），先单压后端基线，再压全链路，对比差值
- 看三个数：QPS、p99 延迟（wrk 的 Latency Distribution）、错误数
- 限流实验开着时压测会大量 429——先关 limit_req 再做纯性能压测
