# MySQL 聚合查询练习

> 场景：年级-班级-学生成绩。覆盖 GROUP BY、聚合函数、多表联查、HAVING、窗口函数、ROLLUP、子查询、SQL 易错陷阱。
> 找茬题的错误 SQL 中：错题 1 在 MySQL 8 默认模式下真实报错（Error 1054），错题 2 / 5 是**能正常运行但结果错误**的语义陷阱——比报错更危险，面试时要能指出"不报错不代表对"。

## 数据表结构

```sql
CREATE TABLE grade(
    grade_id INT PRIMARY KEY AUTO_INCREMENT COMMENT '年级id',
    grade_name VARCHAR(20) NOT NULL COMMENT '年级名称：初一、初二'
);

CREATE TABLE class_info(
    class_id INT PRIMARY KEY AUTO_INCREMENT,
    grade_id INT NOT NULL COMMENT '所属年级',
    class_name VARCHAR(20) NOT NULL COMMENT '1班、2班',
    FOREIGN KEY (grade_id) REFERENCES grade(grade_id)
);

CREATE TABLE student_score(
    sid INT PRIMARY KEY AUTO_INCREMENT,
    class_id INT NOT NULL,
    student_name VARCHAR(10),
    score DECIMAL(5,1) COMMENT '考试分数，缺考可为NULL',
    FOREIGN KEY (class_id) REFERENCES class_info(class_id)
);
```

## 一、基础练习题

### 习题 1

**需求：** 统计每个班级：总人数、总分、平均分、不及格人数。平均分保留 2 位小数，没有学生的班级也要展示。

```sql
SELECT
    c.class_name, 
    COUNT(s.sid) AS total_num,
    IFNULL(SUM(s.score),0) total_score,
    ROUND(IFNULL(AVG(s.score),0),2) avg_score,
    SUM(IF(s.score<60,1,0)) fail_count
FROM class_info c
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY c.class_id, c.class_name;
```

**要点：**
- `LEFT JOIN` 保留无学生班级（本数据集每个班都有学生，但 habit 要养成）。
- `COUNT(s.sid)` 而非 `COUNT(*)`——LEFT JOIN 下无学生班级会产生一行全 NULL 扩展行，`COUNT(*)` 会把它数成 1 人；`COUNT(s.sid)` 忽略 NULL 恰好得到 0。LEFT JOIN 统计右表行数用 `COUNT(右表主键)`，这是铁律。
- `IFNULL(SUM(s.score),0)` 防止无学生班级 SUM 返回 NULL。

**关于 `GROUP BY` 为什么带 `class_name`（面试常追问）：**

SELECT 里有非聚合字段 `c.class_name`，严格模式 `only_full_group_by` 要求它必须出现在 GROUP BY 里，否则报 Error 1055。但严格来说 **`GROUP BY c.class_id` 单独一行就够**——因为 `class_id` 是主键，MySQL 8 能通过"功能依赖"推断出 class_id 唯一决定 class_name。

写出来 `c.class_id, c.class_name` 的理由不是必须，而是：
1. **跨数据库兼容**：某些分支/老版本（MySQL 5.6）不认功能依赖推断，显式列出最稳。
2. **可读性**：读 SQL 的人一眼看到"按班级分组"，不用回去查 class_id 是啥。
3. **防御性**：一旦表结构变了、`class_id` 不再是主键（或忘了建主键），功能依赖推断失效，单写 `class_id` 会立刻 1055；带上 class_name 也救不了——**主键才是根**。

一句话：技术可省、习惯写出，面试时能讲清"功能依赖靠主键、可省但显式更稳"即可。

### 习题 2

**需求：** 查询班级平均分 ≥ 70 的班级，附带所属年级名称。

```sql
SELECT
    g.grade_name,
    c.class_name,
    COUNT(*) student_count,
    ROUND(AVG(s.score),2) avg_score
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_id,g.grade_name, c.class_id,c.class_name
HAVING avg_score >= 70;
```

**要点：** 聚合后的过滤必须用 `HAVING`，不能用 `WHERE`。

### 习题 3

**需求：** 每个年级总人数、年级平均分、全年级不及格总人数、不及格占比（保留 1 位小数）。

```sql
SELECT
    g.grade_name,
    COUNT(s.sid) grade_total_stu,
    ROUND(AVG(s.score),2) grade_avg,
    SUM(IF(s.score<60,1,0)) grade_fail_num,
    ROUND( SUM(IF(s.score<60,1,0)) / COUNT(s.sid)*100 ,1 ) fail_rate
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_id,g.grade_name;
```

**结果：**

| grade_name | grade_total_stu | grade_avg | grade_fail_num | fail_rate |
|---|---|---|---|---|
| 初一 | 5 | 74.00 | 2 | 40.0 |
| 初二 | 5 | 73.00 | 1 | 20.0 |

### 习题 4

**需求：** 每个年级内部，按照班级平均分排名，使用 `RANK()`，只展示年级前 2 名班级。

```sql
SELECT * FROM (
    SELECT
        g.grade_name,
        c.class_name,
        ROUND(AVG(s.score),2) class_avg,
        RANK() OVER(PARTITION BY g.grade_id ORDER BY AVG(s.score) DESC) rank_no
    FROM grade g
    JOIN class_info c ON g.grade_id = c.grade_id
    LEFT JOIN student_score s ON c.class_id = s.class_id
    GROUP BY g.grade_id,g.grade_name,c.class_id,c.class_name
) t
WHERE t.rank_no <= 2;
```

**要点：** 窗口函数 `RANK()` 不能直接在外层 `WHERE` 过滤（执行顺序问题），必须包一层子查询。

### 习题 5

**需求：** 每个班级分段统计人数：<60、60~79、80~89、≥90。

```sql
SELECT
    c.class_name,
    SUM(CASE WHEN s.score <60 THEN 1 ELSE 0 END) less60,
    SUM(CASE WHEN s.score BETWEEN 60 AND 79 THEN 1 ELSE 0 END) score60_79,
    SUM(CASE WHEN s.score BETWEEN 80 AND 89 THEN 1 ELSE 0 END) score80_89,
    SUM(CASE WHEN s.score >=90 THEN 1 ELSE 0 END) more90
FROM class_info c
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY c.class_id,c.class_name;
```

**结果：**

| class_name | less60 | score60_79 | score80_89 | more90 |
|---|---|---|---|---|
| 初一1班 | 1 | 0 | 1 | 1 |
| 初一2班 | 1 | 1 | 0 | 0 |
| 初二1班 | 0 | 0 | 1 | 1 |
| 初二2班 | 1 | 2 | 0 | 0 |

## 二、找茬错题训练

> 每题给出「错误 SQL」和「修正 SQL」。错误 SQL 在 MySQL 8 默认严格模式下大多会直接报错，下面标注了真实报错信息。

### 错题 1：WHERE 用聚合字段

**需求：** 查出平均分 70 分及以上的班级，展示年级名、班级名、人数、平均分。

**错误 SQL：**

```sql
SELECT
    g.grade_name,
    c.class_name,
    COUNT(s.score) AS student_num,
    ROUND(AVG(s.score),2) avg_score
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
WHERE avg_score >=70
GROUP BY g.grade_name, c.class_name;
```

**真实报错：** `Error 1054 (42S22): Unknown column 'avg_score' in 'where clause'`

**错误点：**
1. `WHERE` 使用聚合字段 `avg_score`，语法错误——聚合过滤要用 `HAVING`。

**修正 SQL：**

```sql
SELECT
    g.grade_name,
    c.class_name,
    COUNT(*) AS student_num,
    ROUND(AVG(s.score),2) avg_score
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_id, g.grade_name, c.class_id, c.class_name
HAVING avg_score >= 70;
```

### 错题 2：INNER JOIN 丢维度 + 除零风险

**需求：** 每个年级：总学生数、不及格人数、不及格占比。

**错误 SQL：**

```sql
SELECT
    g.grade_name,
    COUNT(s.sid) total_stu,
    SUM(IF(score<60,1,0)) fail_num,
    ROUND(SUM(IF(score<60,1,0)) / COUNT(s.sid)*100,1) fail_rate
FROM grade g
INNER JOIN class_info c ON g.grade_id=c.grade_id
INNER JOIN student_score s ON c.class_id=s.class_id
GROUP BY g.grade_name;
```

**说明：** 这条 SQL 在 8.0 默认 `only_full_group_by` 下**能正常执行**（非聚合列 `g.grade_name` 已在 GROUP BY 中，该模式从不要求 GROUP BY 包含主键）。它的真实问题是语义错误：

**错误点：**
1. `INNER JOIN` 丢失无学生班级 / 年级——需求要每个年级，无学生的年级不会出现。
2. 总人数为 0 时除法出现除零异常（除零风险在数据有 NULL 时才会触发，本数据集不出现）。

**修正 SQL：**

```sql
SELECT
    g.grade_name,
    COUNT(s.sid) total_stu,
    SUM(IF(s.score<60,1,0)) fail_num,
    ROUND(SUM(IF(s.score<60,1,0)) / COUNT(s.sid)*100,1) fail_rate
FROM grade g
JOIN class_info c ON g.grade_id=c.grade_id
LEFT JOIN student_score s ON c.class_id=s.class_id
GROUP BY g.grade_id, g.grade_name;
```

### 错题 3：窗口函数缺 PARTITION BY

**需求：** 每个年级内部，班级平均分排名。

**错误 SQL：**

```sql
SELECT
    g.grade_name,
    c.class_name,
    ROUND(AVG(s.score),2) avg_score,
    RANK() OVER(ORDER BY AVG(s.score) DESC) rn
FROM grade g
JOIN class_info c ON g.grade_id=c.grade_id
LEFT JOIN student_score s ON c.class_id=s.class_id
GROUP BY g.grade_id,g.grade_name,c.class_id,c.class_name;
```

**真实结果（不报错但语义错）：** `rn` 变成全校排名，不是分年级排名。

| grade_name | class_name | avg_score | rn |
|---|---|---|---|
| 初一 | 初一1班 | 78.33 | 2 |
| 初一 | 初一2班 | 67.50 | 3 |
| 初二 | 初二1班 | 88.50 | 1 |
| 初二 | 初二2班 | 62.67 | 4 |

**错误点：** 缺少 `PARTITION BY g.grade_id`，变成全校排名，不是分年级排名。

**修正 SQL：**

```sql
SELECT
    g.grade_name,
    c.class_name,
    ROUND(AVG(s.score),2) avg_score,
    RANK() OVER(PARTITION BY g.grade_id ORDER BY AVG(s.score) DESC) rn
FROM grade g
JOIN class_info c ON g.grade_id=c.grade_id
LEFT JOIN student_score s ON c.class_id=s.class_id
GROUP BY g.grade_id,g.grade_name,c.class_id,c.class_name;
```

### 错题 4：ROLLUP 汇总行 NULL 没兜底

**需求：** 统计各班数据，自动生成年级小计、全校合计。

**错误 SQL：**

```sql
SELECT
    g.grade_name,
    c.class_name,
    COUNT(s.sid) people_num,
    ROUND(AVG(s.score), 2) avg_score
FROM grade g
LEFT JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_name, c.class_name WITH ROLLUP;
```

**真实结果：** 汇总行 `grade_name` / `class_name` 显示 NULL，不友好。

| grade_name | class_name | people_num | avg_score |
|---|---|---|---|
| 初一 | 初一1班 | 3 | 78.33 |
| 初一 | 初一2班 | 2 | 67.50 |
| 初一 | NULL | 5 | 74.00 |
| 初二 | 初二1班 | 2 | 88.50 |
| 初二 | 初二2班 | 3 | 62.67 |
| 初二 | NULL | 5 | 73.00 |
| NULL | NULL | 10 | 73.50 |

**错误点：**
1. LEFT JOIN 链下无学生班级会产生全 NULL 扩展行，人数统计应用 `COUNT(s.sid)` 而非 `COUNT(*)`（后者把扩展行数成 1 人）。
2. NULL 平均分没有兜底。
3. 汇总行名称显示 NULL 不友好。

**修正 SQL：**

```sql
SELECT
    IFNULL(g.grade_name, '全校汇总') AS grade_name,
    IFNULL(c.class_name, '年级小计') AS class_name,
    COUNT(s.sid) AS people_num,
    ROUND(IFNULL(AVG(s.score), 0), 2) AS avg_score
FROM grade g
LEFT JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_name, c.class_name WITH ROLLUP;
```

### 错题 5：子查询嵌套 + NULL 污染平均分

**需求：** 找出年级平均分高于全校平均分的年级。

**错误 SQL：**

```sql
SELECT
    g.grade_name,
    COUNT(s.sid) grade_people,
    AVG(s.score) grade_avg
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_name
HAVING grade_avg > (
    SELECT AVG(score) FROM student_score
);
```

**说明：** 这条 SQL 在 8.0 默认 `only_full_group_by` 下**能正常执行**（非聚合列 `g.grade_name` 已在 GROUP BY 中）。它的真实问题是语义陷阱：

**错误点：**
1. `INNER JOIN` 丢失无数据年级（需求是"找出年级"，无学生年级直接消失）。
2. `AVG()` 本身忽略 NULL，缺考分数**不会**拉低平均；若业务要求缺考按 0 分计入，才需要 `AVG(IFNULL(score,0))`——这是语义选择而非纠错。

**修正 SQL：**

```sql
SELECT
    g.grade_name,
    COUNT(s.sid) AS grade_people,
    ROUND(IFNULL(AVG(s.score), 0), 2) AS grade_avg
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_id, g.grade_name
HAVING grade_avg > (
    SELECT ROUND(AVG(score), 2) FROM student_score
);
```

**结果：** 只有"初一"出现。初二年级平均 73.00，低于全校平均 73.50（本数据集无人缺考，73.50 就是普通 `AVG` 的结果，与 NULL 无关），所以被 `HAVING` 过滤。这是修正 SQL 的语义本身如此，不是 bug。

## 三、拔高题

### ROLLUP 多级汇总

**需求：** 生成各班明细、年级小计、全校总计报表。

```sql
SELECT
    IFNULL(g.grade_name,'全校总计') grade_name,
    IFNULL(c.class_name,'年级小计') class_name,
    COUNT(s.sid) total_people,
    ROUND(IFNULL(AVG(s.score),0),2) avg_score
FROM grade g
JOIN class_info c ON g.grade_id = c.grade_id
LEFT JOIN student_score s ON c.class_id = s.class_id
GROUP BY g.grade_name, c.class_name WITH ROLLUP;
```

### 高于本班平均分的学生

**需求：** 查询每个班里分数高于本班平均分的学生名单。

```sql
SELECT
    c.class_name,
    s.student_name,
    s.score,
    class_avg.class_avg_score
FROM student_score s
JOIN class_info c ON s.class_id = c.class_id
JOIN (
    SELECT class_id, ROUND(AVG(score),2) class_avg_score
    FROM student_score
    GROUP BY class_id
) class_avg ON s.class_id = class_avg.class_id
WHERE s.score > class_avg.class_avg_score;
```

**结果：**

| class_name | student_name | score | class_avg_score |
|---|---|---|---|
| 初一1班 | 小刚 | 92.0 | 78.33 |
| 初一1班 | 小明 | 88.0 | 78.33 |
| 初一2班 | 小李 | 76.0 | 67.50 |
| 初二1班 | 小王 | 95.0 | 88.50 |
| 初二2班 | 小赵 | 77.0 | 62.67 |
| 初二2班 | 小孙 | 66.0 | 62.67 |

## 聚合查询通用避坑总结

1. **单表统计用 `COUNT(*)`**（优化器选最小索引）；**LEFT JOIN 统计右表行数必须 `COUNT(右表主键)`**——无匹配的扩展行全 NULL，`COUNT(*)` 会把它数成 1 人；`COUNT(普通字段)` 忽略 NULL，语义按场景选。
2. **保留全部维度数据**（年级、班级），成绩表用 `LEFT JOIN`，`INNER JOIN` 会丢无数据维度。
3. **`WHERE` 过滤原始行；`HAVING` 过滤聚合之后结果**——这是最容易写错的点。
4. **`GROUP BY` 严格模式**：SELECT 中非聚合字段必须出现在 GROUP BY 中、或功能依赖于 GROUP BY 列（如主键）——`only_full_group_by` 从不要求 GROUP BY 必须包含主键。主键在 GROUP BY 时 MySQL 8 能通过"功能依赖"推断它唯一决定其他列，此时其他列可省——但显式写出跨库兼容、可读性更好。
5. **NULL 数值计算使用 `IFNULL(字段, 0)` 兜底**防除零；注意 `AVG()` 本身忽略 NULL，把 NULL 当 0 计入（`AVG(IFNULL(x,0))`）才会拉低平均——按业务语义选择。
6. **窗口函数分组排名必须加 `PARTITION BY`**，否则变成全局排名。
7. **ROLLUP 汇总行配合 `IFNULL` 美化**，否则汇总行显示 NULL 难读。
