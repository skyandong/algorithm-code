# system-design 系统设计专题

> 面试系统设计的**决策过程**训练场：不是背架构图，是学会问需求、算数字、讲 trade-off、按瓶颈演进。全模块按 **4S 框架**组织：Scenario（场景约束）→ Storage（存储选型）→ Scale（容量估算）→ Schema/演进。

## 实验数据锚点表

跑完对照，偏差大说明实现被改坏：

| 实验 | 锚点 | 实测 |
|---|---|---|
| 01 估算 | 短链均值 QPS ≈ 11574；IM 年增 ≈ 170TB；布隆 m ≈ 9.6 亿 bit | ✓ |
| 02 秒杀 | 10 万并发 × 1000 库存：订单 = 1000，0 超卖 0 少卖，三方对账一致 | ✓ |
| 03 短链 | base62 往返一致；布隆 10 万 key 实测误判率 ≈ 1.04% 落在理论 1.00%±20% 内 | ✓ |
| 04 Feed | 纯推 56.8 亿写/天 → 推拉结合削减 >99%；大 V(0.1% 用户) 贡献 >90% 写扩散 | ✓ |
| 05 IM | 乱序+丢包+重复下，上抛序列精确还原 [1..100]，补洞拉取，幂等过滤重复 | ✓ |
| 06 号段 | DB 抖动 200ms 期间发号不中断：fallback=0，单号延迟 << 200ms | ✓ |
| 07 时间轮 | 1000 任务跨 1~10 圈 100% 按预期 tick 触发；取消 100% 生效；槽内残留 0 | ✓ |
| 08 缓存 | 击穿：无锁 100 次 DB 查询 vs 单飞 1 次；穿透：空值缓存 100→1；雪崩：同秒堆积 1000→20 | ✓ |

（时延类数字为量级锚点：µs~ms 级波动属正常，不影响断言。）

## 重点回顾自测清单

- [ ] 4S 各阶段回答什么问题？为什么 Storage 排第二？
- [ ] 必背数字：一天 10⁵ 秒 / 峰值×3~10 / MySQL 写 2k QPS / Redis 10 万 QPS / 单表 2000 万行
- [ ] 通用演进骨架六层，每层"顶不住"的信号是什么？
- [ ] 秒杀六层漏斗每层拦多少？为什么 DECR 失败要 INCR 回滚？为什么 DB 兜底是必须的？
- [ ] 号段双 buffer 为什么选"发到 10% 预取"而不是用完再取？
- [ ] 短链为什么全量缓存合理？301 vs 302 由什么决定？
- [ ] 推和拉的成本模型？大 V 的爆炸项在推拉结合里被消到哪里了？
- [ ] IM 铁三角各解决什么？为什么传输层不追求 exactly-once？
- [ ] 消息表为什么按会话分片不按 uid？多端同步的位点语义像什么？
- [ ] 雪花和号段在"严格单调"上的区别？fencing token 必须用哪个？
- [ ] UUID 做 MySQL 主键的三宗罪？
- [ ] 时间轮的插入公式（轮数/槽位）？轮数字段解决什么？层级时间轮的进位点？
- [ ] 为什么是"删缓存"不是"更缓存"？为什么"先库后删"？
- [ ] 强一致需求的正确路径是什么？为什么不为缓存上分布式事务？
- [ ] 读热点和写热点的解法为什么不同（复制 vs 分片）？
