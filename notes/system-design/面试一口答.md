# 系统设计面试一口答清单

> 从 01~08 篇笔记提炼的「张口就来」清单：被问到要能不带停顿直接说出来。
> 对应章节：`01-方法论与估算` ~ `08-缓存体系设计`，实验代码在 `experiments/`。
>
> **记忆主线：** 系统设计 = 决策过程。四个抓手：**先问再答**（5 问）、**带数字**（必背数值）、**讲 trade-off**（没有银弹只有取舍）、**按瓶颈演进**（LB→横扩→缓存→MQ→分片→多机房）。八个系统全是这四个抓手的排列组合。

---

## 一、方法论与估算（01）

### 1. 系统设计题怎么开始？
先问 5 个约束：QPS/峰值、读写比、一致性、可用性、数据量。没答案就给假设并声明。然后给最简单能跑的方案，按瓶颈逐层演进，全程带数字。

### 2. 必背数字？
一天 ≈10⁵ 秒；峰值 = 均值×3~10；单机 MySQL 写 ~2k QPS；单机 Redis ~10 万 QPS；单表 <2000 万行；1 亿行×100B=10GB。推导链：日活×人均行为÷86400=均值 QPS。

### 3. 通用演进骨架？
LB → 无状态横扩 → 缓存 → MQ 削峰 → 主从/分片 → 多机房。每层解决上一层"顶不住"的信号，跳级（日活 1 万就分库分表）是给自己找运维麻烦。

## 二、秒杀系统（02）

### 4. 怎么防超卖？
三层：Redis DECR 原子预扣挡量；MySQL `UPDATE...WHERE stock>0` 条件更新兜底；对账任务三方比对。**性能靠 Redis，正确性靠 DB**。

### 5. DECR 失败为什么要 INCR 回滚？
多个并发失败者各自看到 -1/-2/-3，都要还原自己的减法，否则余量虚耗、少卖。

### 6. 六层削峰漏斗？
静态化+CDN → nginx 限流 → 答题验证码 → Redis 预扣 → MQ 异步下单 → MySQL 兜底。每层拦一个量级：90% 看热闹的、超频的、机器人、第 1001 名之后的、洪峰对 DB 的冲击。

### 7. 单 key 库存打满一个分片？
库存分桶：总库存拆 N 个子 key，桶内独立 DECR，DB 按总量收口。桶是吞吐优化，正确性不靠桶。

## 三、短链服务（03）

### 8. 短链整体设计？
读写 1000:1，1 亿条 10GB → 全量 Redis 缓存（3 分片）+ 布隆挡穿透 + 302 统计点击。写路径号段双 buffer 发号 + base62（7 位）。

### 9. 发号器选型？
自增（单点+可枚举）、雪花（零依赖但 11 位）、号段双 buffer（DB 压力降 1000 倍，主流）、哈希查重（冲突不可控，不选）。

### 10. 301 还是 302？
要统计选 302（每次回源计数），纯跳转选 301（浏览器缓存）。短链的商业本质是 CTR，选 302+no-cache。

### 11. 布隆误判率公式？
p≈(1-e^(-kn/m))^k，最优 k=(m/n)ln2。1 亿 key、1% 误判约 120MB、7 个哈希。说不存在一定不存在，说存在可能误判。

## 四、Feed 流（04）

### 12. 推拉怎么选？
推写成本 O(粉丝数)、拉读成本 O(关注数)。幂律分布：大 V 推不动、普通人拉不划算 → 推拉结合：大 V 只写发件箱，普通人推收件箱，刷新时合并。朋友圈纯推是因为好友上限 5000 的产品约束。

### 13. 收件箱 score 放什么？
内容的业务分数（发帖时间戳），不是扇出到达时间——异步扇出秒级延迟，到达时间不可比会乱序。排序键要全局可比且不可变。

### 14. Feed 翻页？
cursor（last_score+last_id）不用 offset——深翻页 offset 扫描爆炸。Redis ZREVRANGEBYSCORE 开区间排除边界。

### 15. 大 V 发帖怎么不打爆？
写路径不扩散（O(1)）；读路径按需聚合（成本=关注的大 V 数，与总粉丝无关）；粉丝暴涨监控动态升级策略。

## 五、IM 系统（05）

### 16. 不丢不重不乱序？
不丢：ack+离线收件箱+重传；不重：messageId 幂等去重；不乱序：会话内单调 seqId+断档补洞重组。传输层只能尽力而为，语义在应用层闭环。

### 17. 长连接网关高可用？
状态外置：uid→连接的 route 表存 Redis，网关可随时替换；宕机客户端重连任意网关，route 表刷新后自动路由。心跳+φ-accrual 判死。

### 18. 消息表怎么分片？
按会话 hash：同会话同分片天然保序、读单位是会话。按 uid 要么双写要么双查。分片键=读的单位。

### 19. 多端同步？
每端记 sync_key（已同步的全局提交序号），上线增量拉——binlog 位点消费的语义。

### 20. 万人群消息？
读扩散：只写一次群会话表，成员各自按位点拉，在线推通知不落收件箱，已读每人存一个 read_seq。绝不写扩散。

## 六、分布式 ID（06）

### 21. 三大方案对比？
雪花：零依赖本地生成、趋势递增、时钟回拨是命门；号段：DB 取段本地发、严格单调、双 buffer 零抖动；UUID：无序，MySQL 主键场景否决（要 UUID 形态选 v7）。

### 22. 双 buffer 为什么能消除抖动？
当前段剩 10% 时异步预取下一段，用尽后原子换指针。低水位语义 = 余量消耗时间 ≥ 10× 取段耗时。

### 23. UUID 做主键的灾难？
①随机主键 → B+ 树页分裂 → 写放大+buffer pool 命中率崩+碎片；②36 字符复制进所有二级索引，体积×4.5；③无序丢时间范围查询能力。

### 24. 严格单调为什么不能用雪花？
雪花的序来自各机器本地时钟，跨机器不可比。严格单调必须过单一序列化点：DB 行锁段区间 / Raft 日志 / etcd revision。fencing token 必须严格单调。

## 七、延迟任务（07）

### 25. 三方案？
Redis zset 轮询（量小）、MQ 延迟分桶（档位固定）、时间轮（百万级 O(1)）。Kafka 原生不支持任意延迟——分区顺序消费模型与按时间取冲突。

### 26. 时间轮原理？
60 格环形数组，每格任务链表，指针每秒一格；轮数>0 减一留守，=0 执行摘除。插入：轮数=(d-1)/60，槽=(now+d)%60，O(1)。层级时间轮（秒分时三级降级）表达任意延迟，Kafka/Netty 在用。

### 27. 怎么不丢任务？
三件套：先落 DB 再挂轮；宕机重启重灌 pending；执行按 idempotent_key 幂等。内存是索引，DB 是真相。

### 28. 调度和执行为什么分开？
调度线程只触发不执行——一个慢任务卡住指针，全轮任务集体迟到。隔离故障域。

### 29. 多实例部署？
按 task_id hash 分片，每实例只灌只扫自己的；主备 + 租约仲裁，备机 standby，接管=重灌。

## 八、缓存体系（08）

### 30. 缓存架构怎么讲？
三级：本地（ns，热+可容忍不一致）→ Redis（ms，主力）→ DB（真相）。默认 Cache-Aside 先更库后删缓存；补丁链：延迟双删→binlog 订阅删；强一致直读库。绝不为缓存上分布式事务。

### 31. 为什么删缓存不更缓存？
并发写乱序覆盖会永久错（缓存 v2 库 v3）；删除把重建交给下个读，收敛到库值。

### 32. 三问一句话版？
穿透（查不存在的 key）：布隆+空值；击穿（单热 key 失效）：单飞/逻辑过期；雪崩（大面积失效）：TTL 抖动+多级+熔断。本质都是控制回源速率。

### 33. 热点 key？
读热点：本地缓存+逻辑过期（复制消化读）；写热点：key 分片打散（分片扛写）。复制和分片是扩展性的两个正交方向。

## 考前 60 秒主线串讲

系统设计没有标准答案，只有决策过程——**先问再答、带数字、讲 trade-off、按瓶颈演进**。

数字先落地：一天十万秒、峰值三到十倍、MySQL 写两千、Redis 十万、单表两千万——这些数决定方案在第几层演进。

八个系统一条线：**流量问题**看秒杀（六层漏斗削到 DB 量级）和 Feed（幂律分布推拉分级）；**读写比问题**看短链（1000:1 全量缓存+布隆）；**正确性问题**看 IM（铁三角：seqId 保序、ack 不丢、幂等不重）和秒杀的不超卖（Redis 挡量、DB 兜底、对账收口）；**调度问题**看延迟任务（时间轮 O(1)，内存索引 DB 真相）；**标识问题**看分布式 ID（雪花趋势、号段严格，fencing 要严格）；**总纲是缓存**（三级分层，一致性的终点是强一致就别用缓存）。

每个系统反复出现的同一句话：**性能在缓存层做，正确性在存储层做，中间用幂等和重试填缝**。
