# 证书体系：网站怎么证明"我是我"

> **核心认知：证书 = 公钥 + 域名 + 有效期，由 CA 背书签名。
> 整套体系解决"我怎么知道这个公钥真的是淘宝的"——
> 你不信任网站，你信任操作系统预装的根证书，根证书信任中间 CA，中间 CA 信任网站。
> 验证证书 = 沿这条信任链逐级验签 + 查有效期 + 对域名。**

---

## 先想一个问题

握手时服务器发来"我是 www.taobao.com，我的公钥是 XXX"。

**凭什么信？** 如果中间人拦截流量，回一句"我是 www.taobao.com，我的公钥是【中间人的】"，之后你们的加密通道其实建在中间人手里——这就是 MITM。

裸公钥毫无可信度。需要**第三方背书**：CA（证书颁发机构）。

## 证书是什么：一张有签名的介绍信

```
证书 {
    域名:      www.demo.local        ← 我是谁（现代看 SAN 字段，不是 CN）
    公钥:      xxxx                  ← 我的公钥
    有效期:    2026-01-01 ~ 2026-04-01
    签发者:    Let's Encrypt         ← 谁给我背的书
    签名:      <签发者用私钥对以上内容的签名>
}
```

类比：介绍信本身谁都能写，**关键是盖的那个章**。章（CA 私钥）造不了假，因为验证章的"印模"（CA 公钥）早已预装在你的操作系统里。

## 信任链：三级背书

```
Root CA（根证书，自签名）
  │  预装在你的 macOS/Windows/浏览器里——整个体系的信任起点
  │  私钥离线锁在保险库，十年才换
  ▼ 签发
Intermediate CA（中间 CA，如 Let's Encrypt 的 R10/R11（RSA）、E5/E6（ECDSA）等——老的 X3 已于 2020 年退役）
  │  在线干活，每次签发证书都经过它
  ▼ 签发
Leaf（叶子证书，www.demo.local）
  │  你的网站证书，几个月一换
```

**为什么要三级？** 根私钥绝不能上网。日常签发全部由中间 CA 完成，就算中间 CA 私钥泄露，吊销重签中间证书就行，根基不动。

浏览器验证（逐级验签）：用中间公钥验证叶子的签名 → 用根公钥验证中间的签名 → 根在自己信任库里 → 通过。

## 验证不止验签，是一套组合拳

```
① 签名链：  逐级验签，最终到达受信任的根
② 有效期：  notBefore ≤ 现在 ≤ notAfter
③ 域名匹配： 访问的域名必须在证书的 SAN 列表里
④ 用途约束： 证书的 KeyUsage/EKU 得对得上（服务端证书不能拿来当 CA 用）
⑤ 吊销状态： CRL / OCSP（实践中常被弱化，见下）
```

任何一条不过 → 浏览器大红警告。你在浏览器里见过的每种证书报错，都是这里某一条挂了：

| 浏览器报错 | 挂了哪条 |
|-----------|---------|
| `ERR_CERT_AUTHORITY_INVALID` | ①（CA 不受信任/链断了） |
| `ERR_CERT_DATE_INVALID` | ②（过期） |
| `ERR_CERT_COMMON_NAME_INVALID` | ③（域名不在 SAN） |

## 两个高频生产事故

**事故一：服务器只发了叶子证书（链不完整）**

服务器应当发送 [叶子 + 中间] 两张。只发叶子时，客户端手里没有中间公钥，验签链条断裂。有的浏览器会按证书里的 AIA 字段自动下载中间证书"自救"，有的不会——于是出现诡异现象：**同一个网址，一部分用户正常一部分报错**。Nginx 配置必须是 fullchain（叶子+中间拼接），不是只有叶子。

**事故二：内网自建 CA 没装到客户端**

公司内部用自建 CA 给内部域名签证书是常规操作，但忘了把 CA 证书装进客户端信任库，全员报 `AUTHORITY_INVALID`。修法就是把 CA 证书导入操作系统信任库（macOS: 钥匙串访问 / Linux: /usr/local/share/ca-certificates/）。

## 吊销：证书还没过期但已作废

私钥泄露了，证书必须提前作废：

- **CRL**：CA 定期发布吊销名单，客户端拉取——名单大、更新慢
- **OCSP**：实时查询"这张证书吊销没"——快，但暴露隐私（CA 知道你访问了谁），且查不到时浏览器默认"软失败"放行
- **OCSP Stapling**：服务器自己定时取回 OCSP 响应，握手时直接附带——最实用的折中
- **终极简化**：把证书有效期缩到 24 小时，"过期"取代"吊销"（云原生/Istio 的玩法）
