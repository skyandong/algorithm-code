# TLS 1.3 握手：快在哪、安全在哪

> **核心认知：TLS 1.3 快的核心就一招——客户端第一封信就把 DH 公钥带上（猜服务器会选哪条曲线），
> 服务器回信时也带上它的公钥，第一个来回双方就都拿到钥匙了。
> 省下的那一轮 RTT，就是 1.2 里"客户端补发 DH 公钥"的那一封空跑。
> 安全提升同理一句话：把 1.2 里"每次连接共用服务器私钥"的坑全填了。**

---

## 先看怎么省出一轮

**1.2 的浪费**：客户端第一封 ClientHello 只报家底不带钥匙；等服务器回完信，客户端才补发自己的 DH 公钥（ClientKeyExchange）——这就是第二个 RTT 的由来。

**1.3 的做法**：ClientHello 里直接带 `key_share` 扩展（我的 DH 公钥先押上）。服务器回 ServerHello 时也带 key_share。**一个来回，钥匙到手：**

```
客户端                                          服务器
  │ ① ClientHello + key_share ────────────────▶ │
  │    （明文：报家底 + 押上我的DH公钥）           │
  │                                              │
  │ ◀──────────── ServerHello + key_share ───── │ ← 此刻双方都能算出密钥了！
  │ ◀──────────── {EncryptedExtensions}  加密 ✓ │
  │ ◀──────────── {Certificate}          加密 ✓ │
  │ ◀──────────── {CertificateVerify}    加密 ✓ │
  │ ◀──────────── {Finished}             加密 ✓ │
  │                                              │
  │ ② {Finished}(加密) ───────────────────────▶ │
  │                                              │
  │ ◀══════ 加密通信 ══════════════════════════▶ │
```

## 四个肉眼可见的改进

### 1. 证书也加密了

1.2 的 Certificate 是明文飞的——路边嗅探的人能看到你访问的网站用哪个 CA、什么证书。
1.3 从 ServerHello 之后**所有握手消息全部加密**（服务器一拿到 DH 公钥就立刻切换）。

### 2. ChangeCipherSpec 的切换功能没了

1.2 那条"下面开始加密"的通知信，其切换加密的功能被密钥派生体系取代——本身就明确了什么时候开始加密，不用再喊一嗓子。但消息本身没有被彻底删除：RFC 8446 附录 D.4 为兼容中间件保留了不改变密码状态的 dummy CCS 记录，兼容模式下抓包仍能看到。

### 3. 密码套件瘦身

```
1.2: TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256   ← 密钥交换+认证+加密+哈希 四合一
1.3: TLS_AES_128_GCM_SHA256                  ← 只剩 加密+哈希

为什么能砍：密钥交换改由 key_share / pre_shared_key 扩展协商——1.3 支持 (EC)DHE（含 ffdhe 有限域 DHE）和 PSK（psk_ke / psk_dhe_ke），并非没得选；签名算法也挪到独立扩展协商
```

### 4. 降级攻击有疫苗了

服务器如果被迫降到 1.2，会在 ServerHello 的 random 后 8 字节埋暗号 `DOWNGRD\x01`。1.3 客户端看到这个标记直接断连——中间人再也压不动版本。

## 三层密钥：保险柜套保险柜

1.3 的密钥派生像俄罗斯套娃，每一层从上一层"长"出来：

```
Early Secret     （来自 PSK，给 0-RTT 用）
   ↓ 混入 ECDHE 共享密钥
Handshake Secret （加密握手消息：证书、Finished）
   ↓ 再混合
Master Secret    （加密业务数据）
```

**为什么套三层？** 一层的钥匙被破解也只损失那一层：0-RTT 数据泄了不影响握手，握手的密钥泄了不影响业务数据。**隔离爆炸半径。**

（1.2 只有一个 master_secret 一把抓，这是 1.3 在密码学工程上的重要进步。）

---

## 1.2 vs 1.3 速查表

| 维度 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| 握手 RTT | 2-RTT | **1-RTT** |
| RSA 密钥交换 | 支持（无前向安全） | **移除** |
| 证书传输 | 明文 | **加密** |
| ChangeCipherSpec | 有 | 删（仅切换功能，兼容模式保留 dummy 记录） |
| 重协商 / 压缩 | 有（各有攻击） | **全删** |
| 降级防护 | 无 | random 埋 DOWNGRD 暗号 |
| 会话恢复 | SessionID/Ticket | PSK（可 0-RTT） |

**面试一句话**："1.3 把 DH 公钥提前到 ClientHello，第一个 RTT 就完成密钥交换，所以少一轮；同时砍掉 RSA 交换、压缩、重协商这些不安全特性，握手消息从 ServerHello 之后全加密。"

## 对应实验

跑 `go run ./experiments/ handshake`：
- 允许 1.3 → 协商出 `TLS 1.3` + 套件 `TLS_AES_128_GCM_SHA256`（瘦身后的名字）
- 限到 1.2 → 套件名变成 `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`（四合一老名字）

跑 `go run ./experiments/ fail` 最后一个场景：客户端只会 TLS 1.0、服务器要求 1.2+ → `protocol version not supported`（版本协商失败长什么样）。
