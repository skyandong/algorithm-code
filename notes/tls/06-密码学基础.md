# 密码学基础：把四个核心概念吃透

> **核心认知：TLS 用到的密码学就四个词——
> 对称加密（干活）、非对称密钥交换（传钥匙）、签名（证明身份）、哈希（防篡改）。
> 每个概念都只要抓住一个"它解决什么问题"，公式和参数都是细节。**

---

## ① ECDHE：涂料混合的魔法

**问题**：双方要在众目睽睽之下（所有流量可被嗅探）商量出一把相同的秘密钥匙，且秘密本身不能传输。

**Diffie-Hellman 的思路**（用调色打比方）：

```
双方公开约定一种底色（椭圆曲线参数，如 x25519）

客户端：秘密选一个颜色 a（私钥），混出来 aG（公钥），公布
服务器：秘密选一个颜色 b（私钥），混出来 bG（公钥），公布

客户端把 bG 再混上自己的 a  →  abG
服务器把 aG 再混上自己的 b  →  abG   ← 颜色一样，密钥到手

偷听者：知道 aG 和 bG（两个混合结果），却分离不出 a 和 b
        （椭圆曲线离散对数：单向混合，算不回去）
```

**最后那个 E（Ephemeral，临时的）是精髓**：

```
ECDH（静态）：服务器的 DH 密钥写死在证书里，每次连接都用同一对
             → 服务器私钥将来泄露 = 攻击者回放历史流量，全部解密 ✗

ECDHE（临时）：每次连接双方都现生成新的临时密钥对，握手完立即销毁
             → 历史流量的钥匙已经烧掉，泄露服务器私钥也解不开 ✓
```

这就是**前向安全（Forward Secrecy）**：今天的钥匙开了今天的门，明天钥匙丢了，今天说的悄悄话依然是悄悄话。也是 TLS 1.3 干掉 RSA 密钥交换的原因——RSA 交换的 pre-master 用服务器长期公钥加密，私钥一泄历史全裸。

## ② 签名 vs 加密：别混

```
加密：  用对方公钥加密 → 只有对方私钥能解      目的：保密
签名：  用自己私钥对哈希签名 → 任何人用公钥验证  目的：证明"这确实是我发的、没被改"
```

TLS 里签名的两处现身：
- 1.2 的 ServerKeyExchange：给临时 DH 公钥签名（防中间人替换公钥）
- 1.3 的 CertificateVerify：对整个握手抄本签名（一次签名保全部）

## ③ AEAD：加密和防篡改一锅出

TLS 1.2 的 CBC 套件（及更早）：AES 加密 + HMAC 校验，两步操作两个密钥，顺序搞错就出事（历史上多起攻击源于此）。其实 1.2 自己也引入了 AEAD（GCM）套件，只是到 1.3 才强制全 AEAD。

**AEAD**（如 AES-GCM、ChaCha20-Poly1305）：一个原子操作同时完成"加密 + 完整性"：

```
AEAD-Encrypt(明文, 密钥, nonce, 附加数据) → 密文 + 认证标签(tag)
AEAD-Decrypt(密文, 密钥, nonce, 附加数据, tag) → 明文 / 或直接报错

篡改密文任何一个 bit → tag 验证失败 → 整条作废
```

`附加数据`是不需要保密但需要防篡改的上下文（比如记录的类型字段）。TLS 1.3 只留 AEAD，两步合一，想错都错不了。

**选型小知识**：CPU 有 AES 硬件指令 → AES-GCM 最快；没有（老手机/IoT）→ ChaCha20-Poly1305（纯软件实现也快且防时序攻击）。

## ④ HKDF：密钥的流水线

握手拿到的原始共享秘密（abG）不能直接当密钥用——熵分布不均匀、长度也不对。**HKDF** 两步走：

```
Extract（浓缩）：原始材料 + 盐 → 质量均匀的中间密钥
Expand（展开）：中间密钥 + 标签("c hs traffic"等) → 各种用途、各种长度的最终密钥
```

标签就是用途说明书——同一原料，派生出的握手密钥和业务密钥互不相同、互不可推算。

## ⑤ 哈希：贯穿始终的防篡改底座

握手抄本哈希（transcript hash）= 把从头到现在的所有握手消息连起来做一次哈希。Finished 消息、1.3 的签名全都基于它：

> **改任何一个字节 → 哈希变 → 验证失败 → 断连。** 这就是为什么中间人在 TLS 握手里"碰"任何消息都会翻车。

## 30 秒总复习

```
对称加密 AES    快，干活用            "黑话"
ECDHE          隔空传钥匙+前向安全    "调色魔法，用完即焚"
签名           证明身份/防抵赖        "亲笔签名"
AEAD           加密+防篡改一体        "带封条的保险箱"
HKDF           密钥派生流水线         "一把原料出多把专用钥匙"
```
