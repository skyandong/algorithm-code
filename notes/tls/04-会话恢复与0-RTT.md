# 会话恢复与 0-RTT

> **核心认知：握手是全款买房，会话恢复是老业主刷脸进门。
> 核心思想一句话：上次连接建立的信任（密钥材料）存一张"票据"，下次凭票据跳过大部分握手。
> 但天下没有免费的午餐——省到极致的 0-RTT，代价是引入了"重放攻击"这个新坑。**

---

## 为什么需要会话恢复

完整握手的成本：证书传输（几 KB）+ ECDHE 计算 + 2-RTT。对同一个网站，每次都全款重买太浪费。

三代方案演进：

### ① Session ID（1.2 老方案）：服务器记账

```
第一次握手：服务器生成 session ID，把会话状态存在自己内存里
下次连接： 客户端带上 session ID → 服务器查到记录 → 跳过证书/密钥交换
```

问题：**服务器要为每个客户端存状态**。100 万客户端 = 100 万条会话记录；集群部署时，恢复请求落到另一台机器就作废。

### ② Session Ticket（1.2 改良）：服务器把账本交给客户端保管

```
第一次握手：服务器把会话状态加密（用只有服务器知道的 ticket key），
            作为"票据"发给客户端自己存
下次连接： 客户端原样奉还票据 → 服务器解密恢复会话
```

服务器零存储、集群友好。代价：ticket key 一旦泄露，攻击者可解密所有票据恢复历史会话（**丢了前向安全**）。

### ③ PSK（1.3 方案）：Ticket 思想标准化

1.3 把恢复机制统一为 PSK（pre-shared key）：服务器发 `new_session_ticket`，客户端下次在 ClientHello 里带 `pre_shared_key` 扩展认亲。

---

## 0-RTT：恢复的极限形态

普通恢复还要 1-RTT（等服务器确认）。0-RTT 更狠——**ClientHello 里直接夹带加密的应用数据**：

```
普通恢复:  ClientHello ──▶ ServerHello ──▶ 才能发数据     (1-RTT 后有数据)
0-RTT:     ClientHello + [加密数据] ──▶ 立即处理          (0-RTT 就有数据!)
```

服务器一收到 ClientHello 就能解密处理这些"早到的数据"（用 PSK 派生的 early secret 加密）。移动网络 RTT 100ms+，0-RTT 意味着首字节时间砍半。

### 0-RTT 的阿喀琉斯之踵：重放攻击

```
攻击者做的事简单到离谱：
1. 嗅探到 ClientHello + 0-RTT 数据（比如 "POST /transfer?to=attacker&amount=100"）
2. 原样复制，开 N 条 TCP 连接各发一遍
3. 服务器以为是客户端发的，执行 N 次
```

为什么能重放？0-RTT 数据用 PSK 派生的密钥加密，不依赖新的 ECDH——就算 ClientHello 里带了新鲜 key_share（PSK-DHE 模式），0-RTT 数据的加密也不看它，服务器无法区分"第一次发的"和"重放的第一百次"。

### 缓解手段

| 手段 | 思路 |
|------|------|
| 只允许幂等请求 | GET/HEAD 的 0-RTT 数据重放无害；POST 走 1-RTT |
| 服务端去重 | 记录见过的 ClientHello，重复就拒（分布式下要做全局去重，成本高） |
| 应用层一次性 token | 重放了 token 也已作废 |
| 干脆不开 | 银行/支付类场景 |

## 恢复 vs 全新的安全差异（必背）

```
全新握手:  有新鲜 ECDHE → 前向安全 ✓
PSK 恢复:  1.3 默认 psk_dhe_ke，恢复握手也带新鲜 (EC)DHE → 仍有前向安全
           （票据泄露只能解密 0-RTT 数据；失去前向安全的是 psk_ke 模式
             和 0-RTT 数据。"票据泄露=历史可解"只适用 1.2 的 Session Ticket）
0-RTT:     恢复 + 可重放 → 最弱，只配承载幂等请求
```

## 对应实验

跑 `go run ./experiments/ resume`，三次连接对比：

```
第一次连接（全新握手）: resume=false   ← 完整 ECDHE + 证书
第二次连接（会话恢复）: resume=true    ← 同一个客户端配置，带票据回来
新客户端（全新握手）  : resume=false   ← 没票据，老老实实全款
```

`DidResume=true` 就是 Go 告诉你"这次走的是 PSK 恢复路径"。
